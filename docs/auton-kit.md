# 自动赛辅助开发套件

套件对应用户示意图的六步路线，默认标准 V5RC 对抗赛；规则依据为仓库内 Override 2.1（2026-10-08）。第二套路线使用独立参数，暂与第一套共享六步顺序。当前已实现参数编辑、存储、屏幕反馈和路线状态机；实际机构和传感器没有提供端口/限位，因此真机适配器保留 `// TODO` 并返回未就绪，不会启动不完整路线。

## 使用

正常驾驶保留 `opcontrol()` 的 LCD 输出、`chassis::move()` 和 20ms 延时。套件只监听按键，完整输入 **左方向键 `↑↑↓↓←→←→`，再按右侧 `B A`** 才接管屏幕和底盘。逐个按下并松开；相邻按键间隔最多 2 秒，长按只计一次，错误输入重新匹配。驾驶期间没有长按 Y 等其他设置入口。竞赛自动期间不监听手柄。

| 按键 | 设置内功能 |
| --- | --- |
| 左方向键 ← / → | 上一步 / 下一步，六步循环 |
| 左方向键 ↑ / ↓ | 上一个 / 下一个适用变量，跳过本步未使用字段 |
| 右侧 Y / A（左 / 右） | 选择更高 / 更低十进制位，个位到万位 |
| 右侧 X / B（上 / 下） | 当前位加 / 减 1，达到范围边界后限幅 |
| L1 | 在路线 1 / 2 间切换，各自变量独立 |
| R1 | 保存两套路线及选中的路线到 SD |
| R2 | 有改动时尝试保存并退出设置；单步运行中只停止，保持在设置内 |
| L2 | 试跑当前一步；仅无场控连接、手动启用、手柄在线且驾驶摇杆回中时接受 |

字母键位置按 [VEX 官方 V5 手柄说明](https://api.vex.com/v5/home/cpp/Controller/Button.html)：从上方顺时针为 X、A、B、Y。仓库旧仿真手柄绘图的字母位置不同，本套件按真实 V5 布局实现。

设置内不响应驾驶摇杆。单步期间冻结参数、路线选择和保存，R2 停止；断联、场控接入、禁用或模式切换也停止。单步需要人工将机器人放到该步正确起始姿态和持物状态，不自动补跑前面的动作。正式 `autonomous()` 从第一步开始，不受设置中所选步骤影响。

屏幕以 100ms 周期刷新，使用主控 LCD 小号 ASCII 字体：选中路线/步骤/运行阶段与状态、变量名称和五位数值、`^` 所指十进制位、SD 状态（`*` 表示未保存）、当前路线六步所有适用参数、四个驱动电机各自的**实际**电压 mV、转速 rpm、电机轴位置 deg、电流 mA。未使用的参数显示 `-`，缺失电机或错误反馈显示 `ERR`。电机行顺序为端口 `+3、+4、-1、-2`，右侧负端口表示安装反转。设置退出后归还原 LLEMU 屏幕。

## 参数与动作

每步独立保存 D 和时长，不假定所有转角都相同。D 是**相对转角**，0–360 整数度；时间是 0–10000 整数毫秒，精度受 20ms 调度限制。未标定角度和动作时长初值为 0，撞桩/转向超时初值 2000ms 仅为保护初值，并非实测结果。起跑要求使用到的 `forward_ms`、`action_ms` 和两个超时字段大于零。升降/后退为零表示明确跳过该段，D=0 表示保持方向，仍需有效航向反馈。

| 屏幕字段 | 含义 |
| --- | --- |
| `D_deg` / 表格 Ddeg | 该步相对转角，左转为负、右转为正（符号由路线决定） |
| `back_ms` / back | 满电压后退时间 |
| `forward_ms` / fwd | 满电压前进时间；第 5 步为必须收到撞桩反馈的前进上限 |
| `lift_ms` / lift | 满电压抬升时间 |
| `down_ms` / down | 满电压下降时间 |
| `action_ms` / act | Toggle、抓取或松抓发出后的等待时间；第 1 步两处动作共用 |
| `contact_limit_ms` / hit | 等待撞桩的最大时间；到时未撞桩进入故障，不能继续放物 |
| `turn_limit_ms` / turn | 每次转向的最大时间；第 1 步左右两次分别计时 |

1. 左转 D → 一次 Toggle → 右转 D 返回 → 前进直到撞桩 → 下降 → 松抓红 pin。
2. 后退 `back_ms` → 左转 D → 前进 `forward_ms` → 抓 pin+cup。
3. 右转 D 时同步开始抬升 `lift_ms`，转完继续前进直到撞桩 → 下降 → 松抓。到桩立即停止底盘及尚未完成的抬升，并开始下降，不原地补完抬升计时。
4. 后退 `back_ms` → 右转 D → 前进 `forward_ms` → 抓黄 pin。
5. 右转 D → 前进时同步抬升 `lift_ms`，直到撞桩 → 下降 → 松抓。未在 `min(forward_ms, contact_limit_ms)` 内到桩则故障；提前到桩会打断抬升并立即下降，与第 3 步相同。
6. 左转 D → 前进 `forward_ms` 时同步下降 `down_ms` 到导入口；两者独立计时，先结束的执行器先停，全部结束后停车。

“结合”按连续阶段调度及底盘/升降并行实现，不插入人为暂停；后退→转向→前进仍是有次序的动作，不把它改成未指定半径的圆弧。满电压输出命令为 ±12000mV，实际电压受电池和 SDK 限制，屏幕显示真实反馈。转向使用航向反馈及限幅比例控制，增益、最小/最大转向电压和到位容差在 `src/auton/runner.cpp` 标记待标定，不宣称是实测 PID。

## 存储与自动入口

主控需插入可写 SD 卡。启动时读取 `/usd/auton.0`、`/usd/auton.1`；R1 或 R2 退出时保存。文件包含版本、递增序号、所选路线、两套参数和校验和，并检查长度与全部参数范围。写另一槽、关闭后回读校验，保留上一有效槽；最近槽损坏时恢复上一有效版本。两槽都无效时载入失败，不用损坏的值覆盖内存。无 SD 卡时可以在 RAM 调参，但不会跨断电保存；失败状态不会清除 `*`。文件系统缓存或 SD 卡物理损坏仍需实测，不能据此保证任意拔卡时刻均无数据丢失。

`autonomous()` 只调用 `auton::run_selected()`，重新读取已保存参数并复制选中路线执行；读取失败保留 RAM 配置。**SD 中有有效配置时，未保存的 RAM 改动不会被用于正式自动赛**。起跑后修改参数不会改变当前执行快照。总预算从本次回调开始计算，包含读取时间，14.8 秒停止，预留 200ms；每段转向和撞桩还有独立超时，主循环超过 100ms 未更新则故障停止。禁用回调取消目标，手动入口再次清理目标和按键边沿；没有创建后台任务。

## 实机接入与第二套路线

- `src/auton/pros_hardware.cpp`：集中补齐 `ready()`、IMU 累积航向、去抖撞桩输入、升降限位和电压驱动、一次 Toggle/松抓/抓取、全机构停止。设备只构造一次，确定智能/三线端口表后检查冲突；不能仅把 `ready()` 改成 true。
- `src/chassis.cpp`：保留原左 3/4、右 -1/-2 蓝齿轮映射；新增度编码器单位及自动电压/遥测接口，手动摇杆方向沿用原符号，混控增加等比限幅。需核对正电压、转角和真实轮向。
- `src/auton/config.cpp`：`defaults()` 中分别修改 `routes[0]`、`routes[1]` 的初始值；已保存的 SD 配置优先于代码默认值。
- `src/auton/runner.cpp`：动作顺序集中在 `begin_step()`、`enter()`、`next_phase()`，第二套只改角度/时长可直接 L1 切换编辑；若其动作顺序也不同，在此扩展路线标识和相应分支，不修改竞赛回调。
- `src/auton/session.cpp`：场控约束、原屏幕归还和模块生命周期；`src/main.cpp` 只保留薄调用接口。

规则对应：2.1 `<R9>`（英文第 61 页）要求服从场控；`<GG12>/<GG13>`（46–47 页）禁止自动期间人为干预；Match 定义和 `<SC1>` 约束自动时段。第 6 步只做导入口附近定位，**没有实现自动期间人工导入**（`<SG11>`，36 页）。路线的真实轨迹仍需检查自动分界线（`<SG7>/<SG8>`，32–34 页）、持有上限（`<SG6>`，32 页）和机构中间姿态外廓（`<SG2>/<SG3>`，30–31 页），示意图和软件本身不能证明合规。

## 验证

Host 测试 `tests/test_auton.cpp` 覆盖完整/错误/长按 Konami 输入、位选择、两路线隔离、双槽损坏恢复、参数拒绝、六步动作顺序、并行抬升、禁用清零、单步边界、零后退、无撞桩退出、无效航向、调度看门狗及全局自动超时。执行 `python tools/configure_env.py --check`、修改文件的 clang-format 检查、完整 `pros build` 和 host CTest。

尚需实机验证：Konami 按键方向和屏幕字形/列宽、SD 保存后重启及损坏回退、四个电机反馈、启用/禁用/自动转手动、满电压正负方向、真实转角/动作时长、撞桩信号/断线/卡住、升降上下限和尺寸外廓，以及六步路线总时长。未连接硬件时不能声称以上已经通过。
